응집도 (Cohesion) 와 결합도 (Coupling)

소프트웨어 설계 시 모듈의 독립성을 판단하는 가장 중요한 기준입니다.

1. 응집도 (Cohesion) — 높을수록 좋음 (↑)

모듈 내부의 요소들이 서로 얼마나 밀접하게 연관되어 있는지(단일 책임을 잘 수행하는지)를 나타내는 정도입니다.

단계 (높은순) 설명
1. 기능적 (Functional) 모듈 내부의 모든 기능 요소가 단일한 명확한 목적(기능)을 위해 수행됨 (최고!)
2. 순차적 (Sequential) 동일한 입력 데이터를 기반으로 한 활동의 출력이 다음 활동의 입력으로 순차적으로 사용됨
3. 교환적 / 통신적 (Communicational) 동일한 입력과 출력을 사용하여 서로 다른 기능을 독립적으로 수행함
4. 절차적 (Procedural) 모듈이 다수의 관련 기능을 가질 때 순차적으로 실행되는 형태
5. 시간적 (Temporal) 특정 시간(초기화, 종료 등)에 처리되어야 하는 여러 기능을 모아둔 형태
6. 논리적 (Logical) 유사한 성격이나 특정 형태의 취급 데이터를 단순히 묶어서 처리함
7. 우연적 (Coincidental) 모듈 내부 요소들이 서로 아무런 연관 관계가 없음 (최악)

2. 결합도 (Coupling) — 낮을수록 좋음 (↓)

모듈과 모듈 사이에 서로 의존하고 있는 정도를 나타내며, 낮을수록 모듈 간 간섭이 적어 유지보수가 쉽습니다.

단계 (낮은순) 설명
1. 자료 (Data) 모듈 간의 인터페이스가 단순한 데이터(값)만 전달됨 (최고!)
2. 스탬프 (Stamp) 자료구조(객체, 배열 등) 전체가 전달되어 그중 일부 필드만 사용함
3. 제어 (Control) 제어 요소(플래그 등)가 전달되어 다른 모듈의 내부 실행 흐름을 제어함
4. 외부 (External) 어떤 외부 모듈에서 선언된 데이터(변수 등)를 여러 모듈이 공유하여 참조함
5. 공통 (Common) 전역 변수(Global Variable)를 여러 모듈이 함께 공유하고 수정함
6. 내용 (Content) 한 모듈이 다른 모듈의 내부 데이터나 제어 코드를 직접 수정하거나 참조함 (최악)
